## Version and financial boundary

All four corrected products intentionally advance from `0.1.0` to `0.1.1`. New callers inspect fresh version and success pins. QuoteProof's predicate expansion intentionally changes its success contract; other success hashes change with the version. A success pin describes the published contract, not a code attestation. Completed original purchases retain exact-body/key/authorization replay from stored results before current schema, version, price or criteria checks. The regression changes the product version, schema, handler and price after a locally settled fixture and proves one execution/verification/settlement total, including expired authorization replay.

All four canonical payment-requirements hashes remain `282e4f475ed28790146449908abc3da70715d2ed67cd313dafec56dd60ea3467`. Creator/referral frozen terms, public payout flag, both Wrangler configurations, migrations, private operator, payment/preparation/payout accounting and signing/transfer behavior are unchanged. The only x402 execution-module change is published input-schema metadata. The public document error adapter and secret rejection are deliberate bounded API-edge changes.

The helper's local measured download bodies are 24,415–40,487 bytes over three GETs; the saved unsigned envelopes are 1,516–1,658 bytes. These measure packaging and calls only. No token/latency/CPU/conversion/revenue or live-payment improvement is established. Public readback reports zero paid purchases; that is not a count of unique people, synthetic tests or external customers. Seven deliberately selected adversarial Docs tasks from the external audit are not a general success-rate sample.
